## Learned User Preferences

- Prefer minimal, targeted fixes when debugging API/UI failures; for lists and modals favor flat rows (badge + title, simple text links, icon actions) over nested inset panels, accent bars, or pill buttons on bordered cards; session/history modals keep a fixed header/footer with scrollable body only and one-column essentials with expand for detail; truncate tight header and toolbar button labels instead of wrapping; session header actions (My Sessions, End session, language selector) match home/profile control sizing; board editor toolbars use compact icon groups (sketch-board strip as the style reference), with primary add actions as full buttons where space allows; teaching-board workspace buttons and in-card numeric inputs use 32px control height to match that strip—exceptions are modal body fields and the board-tool combobox; modal close buttons match other modals; run `pnpm typecheck` and relevant tests after substantive changes.
- Board sidebar label/value fields (sketch, concept map, matching, comparison table) stay plain text inputs—no Write/Preview chrome and no inline formula/KaTeX in those controls. Home paste notes, the session composer, and the independent-check answer use a rich field that shows formatting in place (still saved as Markdown), with a selection toolbar for bold, italic, code, heading, and lists—no Write/Preview tabs and no formula buttons on that toolbar.
- Local Gemini latency matters: `gemini-3-flash-preview` is an acceptable faster alternative to the repo default when iterating on lesson/chat flows; `gemini-3.5-flash-lite` is fine for cost/speed if structured JSON and PDF OCR stay reliable.
- Do not add topic-specific modules, filenames, or board kinds; lessons and boards stay fully catalog- and prep-driven with no per-subject code paths.

## Learned Workspace Facts

- Teach Milo is a Next.js MVP: Firestore persistence, Gemini for OCR/lessons/chat, session phases through report; auth is email/password with optional Google OAuth (`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` in `.env.local` locally). Styling is hand-written CSS (`globals.css` and CSS modules); Tailwind and its PostCSS plugin are not used.
- Production app deploy is Cloud Build / Cloud Run on GCP project `teach-milo` (`cloudbuild.yaml`: `_SERVICE`/`_REPOSITORY` `teach-milo`, runtime SA `teach-milo-runtime@teach-milo.iam.gserviceaccount.com`, Secret Manager `teach-milo-gemini-key`, `teach-milo-rate-limit-secret`, `teach-milo-google-client-id`, `teach-milo-google-client-secret`, `_APP_ORIGIN`, `_GEMINI_MODEL`; `gcloud run deploy` is `--allow-unauthenticated`); `firebase.json` has no Hosting—use `pnpm exec firebase deploy --only firestore:indexes` (and `firestore:rules` if changed) for Firestore config; wait for new composite indexes before paginated session history in prod. Docker production stage: set `ENV CI=true` then `pnpm prune --prod` only (pnpm 11 rejects `--store-dir` / `--offline` on `prune`). GitHub origin is `kyawoo-23/teach-milo` (`https://github.com/kyawoo-23/teach-milo.git`).
- Local dev expects JDK 21+, Firestore emulator (`pnpm emulators` on 127.0.0.1:8080), and `pnpm dev` in a second terminal; `node scripts/doctor.mjs` checks setup. Plain `pnpm test` skips `tests/firestore.test.ts`, `tests/guests.test.ts`, and the Auth Firestore persistence block in `tests/auth.test.ts` when `FIRESTORE_EMULATOR_HOST` is unset; run `pnpm test:integration` for those suites against the emulator.
- Match browser origin to `APP_ORIGIN` in `.env.local` (typically `http://127.0.0.1:3000`, not `localhost`); Google OAuth redirect URI is `{APP_ORIGIN}/api/auth/google/callback` with the same origin authorized on the Web client. `GOOGLE_CLOUD_PROJECT` is the Firebase/Firestore project id (e.g. `demo-teach-milo` with the emulator), separate from `GEMINI_API_KEY`; the app does not read `.firebaserc` (Firebase CLI only); `pnpm emulators` passes `--project demo-teach-milo`.
- Phase `ready_for_check` (“Milo understood” UI) comes from deterministic `readyForCheck()` on the cumulative ledger after each turn—not Milo’s chat tone; `inferLedgerGaps` can backfill empty demonstration; lesson prep `concerns` no longer gate readiness (they still affect report scoring).
- Lesson prep uses Gemini structured JSON (`LessonGeneratedSchema`); board `BoardStateSchema` must not emit JSON Schema `minimum`/`maximum` on `min`/`max`—Gemini rejects that in large schemas (runtime board bounds live in `compileBoard`, `src/lib/board-catalog.ts`). The model-facing `BoardGeneratedSchema` omits `version` (no JSON Schema `const`); the server stamps `version: 2`.
- Boards are composed from the 17-component catalog in `src/lib/board-catalog.ts` (no topic-specific code); the prompt's board section comes from `catalogPrompt()`. The server re-runs `calculate` (`src/server/calculation.ts`) for board snapshots. Lesson prep runs `prepareTransferReference` (`src/server/transfer-reference.ts`): `verifyNumericTransfer` executes the model's `transfer.numeric` program and stores those metrics as authoritative field `expected` values (`corrected` when Gemini's numbers disagree; invalid programs drop the key); reference prose uses `{{fieldId}}` placeholders filled from those values. Report evaluation passes server `matches` per numeric field so Gemini does not recompute arithmetic; the independent-check card badge uses `statusOf(report.scores.transfer)` like the "Applying it on your own" skill row.
- Gemini client timeouts in `src/server/model.ts` align with route `maxDuration` (120s text, 240s PDF); student turns run `normalizeStudentReply` before `validateStudent` so minor model formatting issues do not fail the whole turn.
- Milo teaching-turn system prompt is `STUDENT_PROMPT` in `src/content/prompts.ts` (prep/evaluate prompts and `languageInstruction()` live there too); `src/server/sessions.ts` appends `languageInstruction(lesson.teachingLanguage)` on each turn and may persist learner-safe `thought` (emotion + reason) on Milo messages from the same structured reply—the evidence ledger stays private. `visibleThought()` in `src/lib/message-thought.ts` drops generic or reply-duplicative reasons; `conversation-message.tsx` shows the rest in a collapsed disclosure excluded from copy. Session chat UI optimistically shows the learner message via `outgoing` in `session-experience.tsx`; scroll effect deps use `messageCount`, `outgoingId`, and `busy`.
- Retention is 7 days by default (`SESSION_RETENTION_DAYS`, `expiresAt()` in `src/server/db.ts`): sessions (and messages/operations), extracted `materials`, and `lessons` all get `expiresAt` on create (materials at upload); original PDF/DOCX bytes are not stored. Finishing to report does not extend expiry. After expiry the API returns 410, history omits the session, and `/session/…` reads as missing. Firestore TTL on `expiresAt` in `firestore.indexes.json` plus `pnpm cleanup` / `scripts/cleanup.mjs` remove documents (TTL is async). Auth cookies in `user_sessions` last 30 days; users can delete a session anytime via `DELETE /api/sessions/:id`. `GET /api/sessions` lists 20 per page (`PAGE_SIZE`) with cursor pagination (`Load more` in the history modal); guest-owned sessions show only under the guest owner until sign-in claim reassigns `ownerId`.
- UI locale cookie `teach-milo-locale` supports `en`, `zh-CN`, `ja`, `ko`, `th` (`src/lib/i18n/locales.ts` and matching JSON dictionaries). Milo teaching-language options add JAPAC codes `vi`, `id`, `ms`, `my`; UI strings for those teaching-only locales live in `src/lib/i18n/teaching-phrases.ts`.
